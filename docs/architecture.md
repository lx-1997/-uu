# RDKClaw 系统架构文档

## 一句话定位

RDKClaw 是 RDK 开发者生态的 AI 中枢——连接云端智能、PC 端工具链和板端执行力，让开发者用自然语言驱动机器人应用的全生命周期。

---

## 为什么需要 RDKClaw？

### 直觉质疑：直接在板端部署一个 AI Agent 不好吗？

这是最常见的问题。答案是：**板端 Agent 必要但不够**。

| 维度 | 纯板端方案的局限 | RDKClaw 三层架构的解法 |
|------|-----------------|----------------------|
| **算力** | RDK X3 仅 2GB 内存、5 TOPS，跑不动大语言模型 | 云端/PC 端承担推理，板端只做执行 |
| **联网** | 板端常在内网/无网环境，无法搜索文档和社区 | PC 端联网检索，结果注入板端 guidance |
| **多设备** | 一个 Agent 只能管一块板子 | RDKClaw 同时管理多台设备，统一调度 |
| **知识更新** | 板端模型知识冻结在训练时间点 | 云端/PC 端实时检索最新文档和方案 |
| **用户体验** | 板端无 GUI，只能命令行交互 | RDK Studio 提供完整 IDE 体验 |
| **安全** | 板端 Agent 有 root 权限，误操作风险高 | RDKClaw 有权限守卫、审批流、通道安全 |
| **社区** | 板端技能无法共享 | SkillHub 让技能在社区流通 |

**核心结论**：板端 OpenClaw 是"手脚"，RDKClaw 是"大脑"。大脑需要看得远（联网）、想得深（大模型）、管得住（权限），这些都不适合放在资源受限的嵌入式板端。

## 各层详解

### 端层：RDK 硬件 + OpenClaw（板端 Agent）

**角色**：执行者——在物理世界中完成任务。

| 组件 | 职责 |
|------|------|
| RDK 硬件 | BPU AI 推理、摄像头采集、GPIO 控制、传感器交互 |
| RDK OS | Ubuntu ARM64 系统、TROS (ROS2)、驱动和运行时 |
| OpenClaw | 板端 AI Agent，执行本地命令、管理技能链、运行推理任务 |

**OpenClaw 的独特价值**：
- 直接访问硬件（BPU、摄像头、GPIO），零网络延迟
- 本地模型推理（不依赖网络）
- 技能链编排（多步板端操作的原子执行）
- 即使断网也能独立工作

**局限**：
- 受限于板端算力（X3 仅 2GB RAM）
- 无法联网检索最新文档
- 知识冻结在本地模型的训练时间点

### 边层：RDK Studio + RDKClaw（PC 端 Agent）

**角色**：大脑——分析、规划、协调。

| 组件 | 职责 |
|------|------|
| RDK Studio | 开发者 IDE，提供设备管理、终端、VNC、文件管理、AI 对话 |
| RDKClaw | PC 端 AI Agent，总调度——接收用户指令，规划方案，协调执行 |

**RDKClaw 的核心能力**：

```
用户自然语言 → RDKClaw 分析意图
                  ├→ 简单任务：直接 device_exec 执行
                  ├→ 知识问题：web_search + 文档检索回答
                  ├→ 复杂任务：assess → delegate 给 OpenClaw
                  └→ 多设备：并行管理多台 RDK 板卡
```

**为什么 RDKClaw 必须在 PC 端**：

1. **大模型推理**：调用 Claude/GPT 等云端大模型，板端跑不动
2. **联网能力**：搜索 D-Robotics 文档、GitHub 仓库、社区帖子
3. **多设备管理**：一个 RDKClaw 实例管理 N 台板卡
4. **安全守卫**：权限审批、敏感信息过滤、通道安全（微信/飞书）
5. **上下文管理**：长对话的 compaction、记忆系统、会话持久化
6. **IDE 集成**：与 RDK Studio 的 UI 深度集成（VNC、终端、文件管理）

### 云层：Agent + 数据 + 大模型

**角色**：基础设施——提供智能和数据服务。

| 组件 | 职责 |
|------|------|
| 云端 Agent | 未来的多租户 RDKClaw 服务（SaaS 化） |
| 数据看板 + 存储 | 用户行为数据、设备遥测、技能使用统计 |
| 地瓜大模型 | D-Robotics 自研模型，针对 RDK 生态微调 |

**云层的战略价值**：
- 数据飞轮：用户使用 → 数据积累 → 模型优化 → 体验提升 → 更多用户
- 模型护城河：基于 RDK 生态数据微调的专属模型，竞品无法复制

### 社区运营层：SkillHub + 文档 + 交流

**角色**：生态——让开发者之间的知识和能力流通。

| 组件 | 职责 |
|------|------|
| SkillHub | 技能市场——开发者发布/安装/共享 Agent 技能 |
| 文档系统 | developer.d-robotics.cc，Agent 可直接检索 |
| 社区交流 | D-Robotics 论坛，Agent 可搜索和发帖 |
| 代码生成 | 基于 Agent 的一句话应用开发 |
| 赛事运营 | AI 竞赛驱动社区活跃度 |

## 双 Agent 协作模型

RDKClaw 和 OpenClaw 的协作是整个架构的灵魂：

```
用户: "帮我在板子上跑一个 YOLO 检测"
         │
         ▼
    ┌─────────┐
    │ RDKClaw │  ① 识别板型（X5, 10 TOPS）
    │ (PC端)  │  ② web_search 查文档，找到最佳方案
    │         │  ③ board_openclaw_assess 评估板端能力
    │         │  ④ 组装 guidance（模型路径、命令、验收标准）
    └────┬────┘
         │ board_openclaw_delegate
         ▼
    ┌─────────┐
    │OpenClaw │  ⑤ 接收 guidance，拆解为执行步骤
    │ (板端)  │  ⑥ 安装依赖、下载模型、配置环境
    │         │  ⑦ 启动推理服务
    │         │  ⑧ 返回执行结果
    └────┬────┘
         │ 结果回传
         ▼
    ┌─────────┐
    │ RDKClaw │  ⑨ 验证结果（device_exec 检查进程）
    │ (PC端)  │  ⑩ 告知用户：浏览器访问 http://板端IP:8000 看画面
    └─────────┘
```

**三种协作工具**：
- `board_openclaw_chat`：轻量交流——了解能力、讨论方案
- `board_openclaw_assess`：评估——判断任务是否适合板端执行
- `board_openclaw_delegate`：委派——确认可行后交付执行

**反向求助**：OpenClaw 也能请求 RDKClaw 帮忙（`[NEED_RDKCLAW]` 协议），比如需要联网搜索信息时。

## 技能系统（Skill）

技能是 Agent 能力的模块化单元，分为三类：

| 类型 | 示例 | 存储位置 |
|------|------|----------|
| 内置技能 | rdk-board-knowledge, rdk-ecosystem | `skills/` 目录 |
| SkillHub 技能 | 社区发布的技能 | ClawHub 远程仓库 |
| 板端技能 | OpenClaw 本地技能 | 板端 `~/.openclaw/skills/` |

**技能的板型感知**：每个技能都有板型识别前置步骤，根据 X3/X5/S100 的差异自动适配命令、模型和路径。

## 权限与安全

```
用户请求 → 通道安全检查 → 权限守卫 → 工具审批 → 执行
              │                │           │
              │                │           └→ 高危工具需用户确认
              │                └→ 检查工具是否允许
              └→ 外部通道（微信/飞书）额外限制
```

- **permission-guard**：工具级权限控制
- **channel-safety**：外部通道（微信/飞书）阻止危险工具
- **tool approval**：高危操作需用户确认（rm -rf、dd、mkfs 等）
- **secret-sanitizer**：自动过滤 API Key、密码等敏感信息

## 上下文管理

长对话的上下文管理是 Agent 稳定运行的关键：

```
消息流入 → Token 估算 → 超限？
                          ├→ Level 1: MicroCompact（压缩工具输出）
                          ├→ Level 2: LLM Compaction（AI 摘要）
                          └→ Level 3: Emergency Truncation（保留最近 6 条）
```

- **9 段式摘要模板**：结构化保留关键信息（目标、决策、文件路径、错误）
- **两段式输出**：`<analysis>` 草稿 + `<summary>` 最终摘要
- **CJK 感知**：中文内容的 token 估算使用独立的字符/token 比率

## 社区赋能路径

```
开发者 ──使用──→ RDK Studio + RDKClaw
   │                    │
   │                    ├→ 一句话开发应用（降低门槛）
   │                    ├→ AI 辅助调试（提高效率）
   │                    └→ 技能自动生成（沉淀经验）
   │                              │
   │                              ▼
   │                         SkillHub
   │                    ┌───────────────┐
   │                    │ 技能发布/安装   │
   │                    │ 社区共享/评价   │
   │                    │ 版本管理/更新   │
   │                    └───────────────┘
   │                              │
   └──────── 复用 ←───────────────┘
```

**赋能闭环**：
1. 开发者用 RDKClaw 完成任务
2. 成功的操作流程自动沉淀为技能
3. 技能发布到 SkillHub
4. 其他开发者安装复用
5. 使用数据反馈优化 Agent 和技能
