# RDK Studio 用户手册

## 1. 产品简介

RDK Studio 是面向地瓜（D-Robotics）RDK 系列开发板的 AI Native 桌面工作台。它把开发板连接、终端、文件管理、远程桌面、在线 IDE、OpenClaw Agent、硬件监控、系统烧录等能力整合到同一个界面中，并通过 AI 助手“小地瓜”把复杂操作简化为自然语言指令。

一句话理解：让开发板开发、部署、调试和运维在一个工作台内完成。

## 2. 适用对象

- 首次接触 RDK 开发板的新手用户
- 需要频繁 SSH、传文件、跑模型的 AI 开发者
- 需要管理多块开发板的测试和运维人员
- 希望通过飞书、微信远程操控开发板的协作者

## 3. 安装与启动

### 3.1 系统要求

- Windows 10/11 64 位，建议 8GB 以上内存
- macOS 13 及以上，建议 Apple Silicon 设备
- 可访问开发板所在局域网，或已配置公网穿透
- 开发板已开启 SSH，已知 IP、用户名、密码

### 3.2 安装步骤

Windows：

1. 获取 RDK Studio 安装包。
2. 双击安装，按向导完成安装。
3. 首次启动后允许防火墙或网络访问权限。

macOS：

1. 下载 `.dmg` 安装包。
2. 将应用拖入 Applications。
3. 首次启动若提示安全限制，请在“系统设置 > 隐私与安全性”中允许打开。

### 3.3 首次启动建议

首次进入后建议按以下顺序完成：

1. 添加开发板
2. 检查网络连通性
3. 打开工作台确认设备状态
4. 进入 OpenClaw 页面完成部署
5. 根据需要配置大模型和飞书/微信通道

## 4. 界面总览

RDK Studio 主要由以下区域组成：

- 左侧导航栏：在工作台、OpenClaw、技能工坊、终端、文件、远程桌面、IDE、烧录、硬件监控等页面之间切换
- 顶部工具栏：显示当前开发板、网络状态、常用工具按钮、设置入口
- 主内容区：当前功能页面的主要操作区域
- 底部 AI 对话坞：与“小地瓜”对话的核心入口

## 5. 快速上手流程

### 5.1 添加开发板

1. 点击左侧底部的设备入口或“添加开发板”按钮。
2. 输入开发板 IP、端口、用户名、密码。
3. 点击连接验证。
4. 连接成功后，设备信息会保存到本地列表中，后续可快速切换。

建议：

- 默认端口通常为 22
- 如果是历史镜像，用户名和密码可能不是 root/root，请按实际环境填写
- 若连接失败，优先检查 PC 与开发板是否在同一网段

### 5.2 查看工作台

进入工作台后，你可以看到：

- 当前开发板名称和 IP
- RDKClaw 状态
- OpenClaw 状态
- SSH 通道是否在线
- CPU、内存、温度、磁盘等资源指标
- 快捷入口，例如打开终端、一句话开发、设备体检

如果顶部 WiFi 图标显示异常，说明开发板虽然已连接，但可能未联网。此时 AI 对话、软件安装、OpenClaw 云端模型访问等能力可能不可用。

### 5.3 使用 AI 对话坞

底部 AI 对话坞支持直接输入自然语言，例如：

- 帮我打开终端
- 帮我连接远程桌面
- 检查这块板子的 OpenClaw 状态
- 帮我看看 CPU 和温度是否正常
- 打开代码编辑器

AI 对话坞支持：

- 流式输出
- Markdown 渲染
- 代码块展示
- 任务进度提示
- 审批确认卡片
- 文件和图片附件

## 6. 核心功能使用说明

### 6.1 终端

终端页面提供基于 SSH 的交互式远程命令行。

适合场景：

- 登录开发板执行命令
- 查看日志
- 安装依赖
- 检查网络、进程、磁盘、服务状态

推荐首批检查命令：

```bash
cat /etc/version
rdkos_info
ip addr
df -h
top
```

### 6.2 文件管理

文件页面可浏览开发板目录、在线编辑文件、上传和下载文件。

常见操作：

- 上传模型、脚本、配置文件
- 编辑开发板上的配置文件
- 下载日志或运行结果

如果页面显示“请先连接开发板”，说明当前没有可用的 SSH 连接。

### 6.3 远程桌面（VNC）

远程桌面用于查看和操作开发板的图形界面。

使用步骤：

1. 选择开发板
2. 进入远程桌面页面
3. 点击连接
4. 等待 VNC 服务启动并加载桌面

如果加载失败，优先检查：

- 开发板是否已安装桌面环境
- `x11vnc` 服务是否正常
- 5900 端口是否可用

### 6.4 在线 IDE

IDE 页面用于访问开发板上的 code-server，获得接近 VS Code 的远程编辑体验。

使用步骤：

1. 进入 IDE 页面
2. 点击连接
3. 若未安装 code-server，点击安装按钮或在终端中手动安装
4. 加载完成后可直接编辑开发板上的代码

适合场景：

- 修改 Python、C++、Shell 脚本
- 浏览项目目录
- 进行轻量调试和远程开发

### 6.5 OpenClaw 管理

OpenClaw 是运行在开发板上的板端全栈 Agent，具备独立规划与执行能力——可自主决策执行步骤、管理技能、处理异常，并在复杂任务中与 RDKClaw 协同工作。

常见操作：

- 一键部署 OpenClaw
- 查看 Gateway 状态
- 配置大模型 API
- 配置飞书集成
- 查看安装日志
- 一键诊断修复

建议部署顺序：

1. 确认开发板已联网
2. 在 OpenClaw 页面运行预检
3. 选择或确认默认模型配置
4. 点击部署
5. 等待安装完成并查看状态栏是否变为运行中

### 6.6 技能工坊

技能工坊用于管理板端技能。

你可以：

- 浏览已安装技能
- 编辑技能定义文件
- 新建技能并部署到开发板
- 通过链接生成技能草稿

适合团队沉淀流程经验，例如：部署脚本、巡检脚本、硬件诊断能力。

### 6.7 系统烧录

烧录页面用于将系统镜像写入 TF 卡或指定介质。

标准流程：

1. 选择板型
2. 选择镜像
3. 开始烧录
4. 等待写入与校验完成
5. 按提示弹出介质并上电验证启动

建议在烧录后立即完成：

- 首次开机验证
- SSH 连通性验证
- OpenClaw 部署验证

### 6.8 硬件监控

硬件监控页面用于查看：

- CPU 温度
- BPU 温度
- 内存占用
- 磁盘占用
- 负载信息

适合场景：

- 长时间推理任务观察
- 排查散热或性能瓶颈
- 远程巡检开发板状态

## 7. 设置说明

设置面板主要分为以下几类：

- AI 引擎：配置大模型厂商、Base URL、API Key、模型 ID
- RDKClaw 人格：调整“小地瓜”的称呼、风格和行为规则
- 策略配置：审批模式、联网权限、记忆功能等
- 飞书集成：配置机器人能力和配对流程
- 微信集成：配置微信 Bot 和扫码绑定
- 安全审计：查看关键操作记录

建议：

- 企业环境优先开启审批模式
- 公网或多人协作环境建议定期检查安全审计

## 8. 远程协作与 IM 通道

RDK Studio 支持通过飞书和微信远程操控开发板。

适用场景：

- 团队成员不在电脑旁时远程下达操作指令
- 测试人员通过 IM 触发巡检或查询状态
- 课程或演示场景下快速回传执行结果

首次启用通常需要完成：

1. 在设置中完成通道配置
2. 生成或输入配对码
3. 在飞书或微信侧完成绑定

## 9. 标准日常工作流

### 9.1 新板上手

1. 烧录系统
2. 启动开发板
3. 添加开发板并完成 SSH 连接
4. 检查工作台状态
5. 部署 OpenClaw
6. 验证终端、文件、VNC、IDE 是否正常

### 9.2 日常开发

1. 打开工作台确认设备在线
2. 用 AI 对话坞或终端执行任务
3. 通过文件页上传脚本或模型
4. 必要时通过 IDE 直接改代码
5. 用硬件监控确认资源占用是否合理

### 9.3 问题排查

1. 先看工作台和顶部状态
2. 再看终端日志和服务状态
3. 检查开发板网络是否正常
4. 若涉及 OpenClaw，先检查 Gateway 和模型 API 连通性

## 10. 常见问题

### 10.1 无法连接开发板

检查项：

- IP 是否正确
- 用户名密码是否正确
- SSH 是否开启
- PC 与开发板是否同网段
- 开发板是否已完成启动

### 10.2 已连接但 AI 功能不可用

优先检查：

- 顶部 WiFi 图标是否提示未联网
- OpenClaw Gateway 是否在运行
- 大模型 API Key、Base URL、模型 ID 是否配置正确

### 10.3 VNC 打不开

优先检查：

- 开发板是否安装桌面环境
- `sudo systemctl status x11vnc`
- 5900 端口是否被占用

### 10.4 IDE 无法加载

优先检查：

- code-server 是否已安装
- `/tmp/code-server.log` 是否有错误
- 开发板磁盘空间是否充足

### 10.5 OpenClaw 部署耗时过长

可能原因：

- 开发板网络较差
- npm 源访问慢
- 依赖安装较多

建议：

- 先运行预检
- 切换更稳定的 npm 源
- 保持网络稳定后再次部署

## 11. 给管理员的建议

- 建议保留一份统一的模型配置模板
- 建议在团队内部规范开发板命名方式
- 建议建立“烧录完成后验收清单”
- 建议把常用巡检操作沉淀为 OpenClaw 技能

## 12. 附录：推荐验收清单

新版本或新设备接入后，建议至少验证以下项目：

1. 工作台能正常显示开发板状态
2. 终端能正常打开并执行命令
3. 文件页面能列目录、上传、下载
4. VNC 能启动并看到桌面
5. IDE 能连接或给出清晰安装提示
6. OpenClaw 能完成部署并显示运行中
7. AI 对话坞能正常响应
8. 烧录页面能完成镜像写入流程
9. 硬件监控能看到基础指标
