# RDKClaw 飞书官方模式联调清单

## 1. 基础配置

- 在 `设置 -> 飞书` 填写 `App ID`、`App Secret`。
- 连接模式选择 `websocket (official)`。
- 私信策略保持 `pairing（默认）`。
- 点击“保存飞书配置”后，点击“重启”通道。

## 2. 飞书开放平台配置

- 应用能力中开启机器人。
- 事件订阅启用 `im.message.receive_v1`。
- 发布应用版本并完成可见范围配置。

## 3. 配对审批链路

- 新用户私信机器人发送任意文本。
- 机器人应返回 6 位配对码。
- 回到 RDK Studio `设置 -> 飞书 -> 配对审批`，应出现对应请求。
- 点击“批准”后，绑定列表应新增该账号。

## 4. 消息执行链路

- 已批准账号再次私信机器人发送问题。
- 机器人应返回 RDKClaw 执行结果（长文本按分片发送）。
- `运行状态` 中最近事件时间应更新。

## 5. 兼容模式回退验证

- 将连接模式切换为 `webhook (compat)` 并保存。
- Webhook 地址使用 `/api/channels/feishu/webhook`。
- 发起 challenge 校验与消息回调应可正常工作。

## 6. 重启恢复验证

- 重启 RDK Studio 服务后重新进入设置页。
- 已绑定账号和待审批请求应从本地持久化恢复。
- 若为 websocket 模式且已启用，应可自动恢复通道运行。

## 7. 会话同步与镜像验证

- 在 RDK Studio 聊天框先发送一条可记忆信息（例如“记住昵称：xxx”）。
- 飞书发送“我的昵称是什么”，应能引用同一上下文回答。
- 飞书收到消息后应先看到“已收到/处理中”回执（按配置）。
- RDK Studio 聊天框中应出现飞书侧 inbound/ack/outbound 镜像消息。
- 在飞书设置里关闭“飞书消息镜像到聊天框”后，镜像应停止但聊天能力不受影响。

## 8. 直连最近活跃会话验证

- 先在 RDK Studio 聊天框发送任意消息，确保“最近活跃 Studio 会话”有值。
- 飞书发送问题后，Studio 聊天应按普通 `user -> ai` 对话展示，不带“飞书用户/飞书回复”前缀。
- 在 Studio 连续追问后，再回飞书追问，应延续同一上下文。
- 若“最近活跃 Studio 会话”为空且飞书账号无绑定会话，应返回提示“请先打开 RDK Studio 聊天窗口并发送一条消息”。

## 9. 异常回退策略

- **回退路由：** 若最近活跃会话为空，但账号存在已绑定会话，飞书消息自动回退到绑定会话继续处理。
- **显式引导：** 若最近活跃会话与绑定会话都不可用，返回明确引导文案，不静默失败。
- **通道降级：** WebSocket 异常时可切到 `webhook (compat)` 保持收发能力。
- **展示降级：** 关闭“飞书消息镜像到聊天框”可快速隔离 UI 噪音，不影响飞书应答。
- **人工兜底：** 在设置页查看“最近通道错误”和“最近活跃 Studio 会话”，确认后执行“重启”通道。

## 10. 设备一致性验证

- 在 Studio 先连接设备，并在聊天框发送一条消息，确认“最近活跃设备”与“设备上报时间”已刷新。
- 飞书发送设备类请求（如“列出 /userdata”），应直接命中 Studio 当前设备，不再出现“无设备上下文”行为。
- 切换 Studio 到另一台设备后再次发送消息，飞书后续请求应自动跟随新设备。
- 若未连接设备直接从飞书发设备类请求，应返回明确提示“请先在 RDK Studio 里连接目标设备”。
