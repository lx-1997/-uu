# RDK Board Progress Reporter（进行 · 过程 · 结果）

## 目标

用户在 RDK Studio 里需要同时看到：

1. **正在做什么**（意图、对象、命令名）  
2. **过程里发生了什么**（关键终端/ros 输出，可截断）  
3. **这一步最终怎样了**（exit 码、是否监听端口、节点是否起来、错误摘要）

仅靠泛化 tool 名会出现「处理数据」「执行脚本」——**无效**。本技能用固定前缀行，让流式区**三样齐全**。

---

## 强制前缀（按顺序使用）

| 前缀 | 含义 | 何时必须发 |
|------|------|------------|
| `[板端·进行]` | 将要做 / 正在做的**具体事**（含包名、launch 文件名、设备路径等） | 每个主要步骤**开始前** |
| `[板端·过程]` | 该步骤的**关键输出**（3～12 行；过长则尾部 + `[…省略…]`） | 命令有**可见输出**时；长耗时中可多次追加 |
| `[板端·结果]` | **结果**：exit 码、后台 PID、端口、topic、或失败原因一句 | 每个主要步骤**结束后**（含后台启动后的确认） |

旧式单行 `[板端] …` 仍可用，但**不得**代替「进行+结果」成对出现；若只用一行，须把「做什么 + 结果」都写进该行。

---

## 标准模板（复制改）

```text
[板端·进行] 环境：source /opt/tros/humble/setup.bash
[板端·结果] 环境：exit=0，已进入 TROS humble

[板端·进行] 探测摄像头：ls -l /dev/video* && v4l2-ctl --list-devices
[板端·过程] （粘贴关键 3～6 行，或末行 + 设备名）
[板端·结果] 探测：/dev/video0 存在，USB camera 已识别

[板端·进行] 启动：ros2 launch <包名> <某.launch.py>（CAM_TYPE=usb，后台）
[板端·过程] （若立刻有日志：贴末 5～10 行；无则跳过）
[板端·结果] 启动：后台已拉起；ss 显示 :8000 LISTEN 或 ros2 node list 含目标节点

[板端·进行] 验收：curl -sI http://127.0.0.1:8000 或 ros2 topic hz <某 topic> -n 5
[板端·过程] （贴返回头或 hz 一行）
[板端·结果] 验收：HTTP 200 / 有帧率输出 → 可认为 demo 已跑通
```

---

## 规则细则

1. **禁止**只发 `[板端·进行]` 不发 `[板端·结果]`（除非该步明确还在跑，下一 chunk 必须补结果）。  
2. **`[板端·过程]`** 在输出超过 12 行时：只保留**最后 12 行**，开头写 `[…省略前 N 行…]`。  
3. **stderr** 非空时：在 `[板端·结果]` 或单独一行 `[板端·过程]` 里带 `stderr: …` 摘要（≤200 字）。  
4. **Web URL** 给用户的：用 `ip -br a` / `hostname -I` 得到的本机 IP，写完整 `http://<IP>:<端口>`；**禁止**文档占位 IP。  
5. **hobot_usb / 设备占用**：重试前先发 `[板端·进行] 清理：…`，再 `[板端·结果] 清理：lsof 无占用 / 仍占用则 …`。

---

## 与 `[TOOL:…]` 的关系

若框架仍产生 `[TOOL:…]`：**每一组 tool 调用**旁，用上述三前缀补全「人类可读版」，避免用户只看 UI 映射。

---

## 收尾（最终回复前）

用列表写清：

- 执行过的 **launch 全路径名**（包 + launch.py）；  
- **验收命令 + 实际看到的现象**；  
- **预览 URL（真实 IP）**。
