# 交互式工作流

## 适用场景
- 任务有多个可行方案，需要用户选择（如：部署方案、模型选型、安装方式）
- 操作有风险，需要用户确认后才能执行（如：烧录、删除、系统级修改）
- 多步骤任务，中间环节需要人工决策
- 用户请求"帮我选"/"给我方案"/"你觉得哪个好"

## 执行流程
1. **识别交互需求**：判断当前任务是否需要用户参与决策
   - 有多个等价方案 → 走 recommendation 流程
   - 有风险操作 → 走 approval 流程
   - 用户已说"自动执行" → 跳过交互，走推荐方案
2. **方案推荐流程**（recommendation）
   - 列出 2-4 个方案，每个包含：ID、标题、一句话描述、是否推荐
   - 标注推荐方案及理由
   - 等待用户选择或"自动执行推荐方案"
   - 用户选择后立即执行，不再二次确认
3. **审批流程**（approval）
   - 描述将要执行的操作、风险等级、影响范围
   - 等待用户决策：允许/拒绝/本会话自动允许/全局自动允许
   - 被拒绝时说明替代方案或安全退出
4. **执行与反馈**
   - 执行选定方案，实时报告进度
   - 完成后给出结果摘要和下一步建议

## 工具映射
| 工具/事件 | 用途 |
|-----------|------|
| recommendation 事件 | 向用户展示多方案选择面板 |
| approval_required 事件 | 向用户展示风险操作确认面板 |
| board_openclaw_assess | 评估板端是否可执行（用于判断方案可行性） |
| web_search / web_fetch | 查文档与仓库（用于生成推荐方案）；板端能力用 assess |

## 输出要求
- 方案列表格式：方案ID + 标题 + 描述 + 推荐标记
- 推荐理由必须基于实际因素（平台能力、性能、兼容性），不能空泛
- 用户选择后的执行结果需包含：执行状态、关键输出、下一步
- 审批被拒绝时不输出负面情绪，给出替代路径

## 禁止事项
- 不在有明确最优解时强行列多方案（浪费用户时间）
- 不在用户已选"自动执行"后仍反复确认
- 不伪造方案差异（如果方案本质相同就不要拆分）
- 不在低风险操作中触发审批流程
- 不隐藏方案的缺点或风险
